# 非开发者如何开发一个指令包

你不会写代码。你也不需要。

---

## 一、你能提供什么

经验。养花十年知道根腐病的叶子什么样，知道蚜虫用洗衣粉水就能杀。这些经验大模型学不到，API 文档里没有，只在你的脑子里。

text-cli 让这些经验变成可调用的服务——别人发来"叶子黄了"，你的经验给出诊断。

---

## 二、你需要写什么

两个 Markdown 文件。

### 2.1 经验笔记

每篇笔记一个病症，五段结构：

```markdown
# 病名

## 症状
（你观察到的——叶子什么样、土什么颜色、有没有虫子）

## 多发条件
（你总结的——什么季节、什么养护方式容易出这个问题）

## 容易误判的情况
（你踩过的坑——被当成什么病但其实是这个）

## 处理方案
（你验证过的——一步步怎么做）

## 我的血泪教训
（你愿意分享的个人经历——可有可无）
```

### 2.2 症状索引

一行一条，症状→文件名：

```
根腐病.md ← 叶从下往上黄、一碰就掉、茎发黑、土面白霉
黄叶病.md ← 新叶黄但叶脉绿、老叶正常
蚜虫.md ← 嫩芽上芝麻大小的虫子密密麻麻
```

---

## 三、平台替你做了什么

```
你的 Markdown ──→ 症状索引读入 ──→ AI 查表匹配
                                    ↓
                              读对应经验文件
                                    ↓
                              AI 生成诊断方案
                                    ↓
                              返回给调用方
```

你只维护两个 Markdown。索引导诊、文件读取、AI 推理——平台自动完成。

---

## 四、你的知识是安全的

调用方问"月季叶子从下面开始发黄，一碰就掉"——他们拿到的是"根腐病，停水通风剪烂根换土"。你的经验原文不出你部署的服务边界。

不是卖知识——是卖**知识结合实际问题的解决方案**。每一条诊断都是针对具体症状的一对一方案。

---

## 五、怎么发布

你的 AI 伙伴帮你完成部署：

```
AI:text-cli;install,flower-care
```

发布后，别人通过 /skill 端点发现你的诊断服务，发来症状描述，你的经验给出诊断。每调一次，你获得一次收入。

---

## 六、怎么持续更新

有了新经验——"原来多肉晒太阳太少也会出问题"——在索引里加一行，在 knowledge/ 下加一篇新笔记。不需要改任何其他东西。路径自动覆盖新病症。

你的经验越多，索引越密，诊断越准——时间是你的护城河。

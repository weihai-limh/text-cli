## 一、你被什么困扰

AI 需要使用工具——只用推理解决不了计算、查天气、搜地图这类需要确定性的机械任务。

但现在调用工具的方式太重：每件工具都要占用上下文去读它的 JSON Schema、理解参数语义。工具越多，上下文越膨胀。

更糟的是，AI 发现工具的能力是被动式的——只能匹配上下文中已暴露的工具。一个端点还有什么工具可以用，不提前告诉 AI 就不知道。

收口：**AI 需要工具，但调用太重、发现太被动。**

---

## 二、text-cli 解决什么

text-cli 是分布式指令分发骨架。部署到一台机器后，这台机器上的服务和工具作为"能力源"对外提供能力。

任何人都能写指令包装到骨架上。任何 Web 在线服务（API、MCP、脚本）接进来就是一条或多条指令。

在协议层，任何满足协议的请求都可以通过 HTTP 从能力源获取能力。无论你是人、是 AI、在 webchat 里还是在 agent 里——同一个请求，同一个响应。

就像魔法卷轴：你不必有运行高级魔法的魔力。撕开它，能力源为你的魔法释放赋能。

## 三、开始用

源码在 [GitHub](https://github.com/weihai-limh/text-cli)。

**🟢 快速通道（2 分钟）**

```bash
git clone → 配置 → 启动 → 预置指令直接可用
```

```bash
curl -X POST <端点>/text-cli/cli \
  -H "Content-Type: application/json" \
  -d '{"prompt":"AI:tc-datetime;now"}'
```

效果信号：`{"rst_types":"text","rst_data":{"text":"2026-07-15 18:31:00 CST"}}`——你拿到了当前时间。

**🔵 完整通道（10 分钟）**

换一台机器部署，换 IP 调同一指令：

```bash
curl -X POST http://10.168.1.122/text-cli/cli \
  -H "Content-Type: application/json" \
  -d '{"prompt":"AI:text-cli;query"}'
```

效果信号：返回另一台机器的指令列表——能力不同，调用方式一样。AI 发同一行 query 也能看到。

## 四、你获得什么能力

- **指令注册与分发**：任何 Web 在线服务（API、MCP、脚本）注册后就是一条指令
- **路径编排**：多条指令串联成链——先查天气，再给穿衣建议
- **分布式分发**：多台机器各自部署，各自暴露不同的能力。换 IP 就是换能力源，调用方式不变
- **聚合降级**：同一类能力有多个提供方时自动切换，调用方不感知

## 五、三把能力的钥匙

| 钥匙 | 它赋予的能力 | 一个真实的场景 |
| copilot（127.0.0.1） | 操作本机文件系统、shell、Git、终端 | 你说"帮我把这份文档推送到 GitHub"，AI 调 files;read → git;push |
| service（0.0.0.0） | 挂载指令包、暴露外部服务 | 你在内网部署翻译服务，局域网任何人都能 curl |
| endpoint（公网） | 鉴权+路由+转发+记账，对接公网 | 你给外部调用方签一个 Access Token，他只看到一个入口 |

## 六、三种接入模式

| 模式 | 包含 | 适用场景 |
|------|------|---------|
| **本机模式** | 仅 copilot | 个人开发者，AI Agent 操作本机文件/Git/shell |
| **内网模式** | copilot + service | 家庭/团队内网，共享指令包，多台机器各自暴露能力 |
| **公网模式** | copilot + service + endpoint | 对外提供服务，Access Token 鉴权，多 service 聚合 |

升级是加法——公网模式的用户仍然可以 curl 本机 copilot。

## 七、预设

| 主题 | 说明 |
|------|------|
| **开箱即用** | `git clone` → 改一个配置 → 启动。预置指令直接可用 |
| **匿名模式** | 默认不需要 token。内网环境下 curl 即用，A2 copilot 也无需鉴权 |
| **生产模式** | 开启三层安全防线（IP 黑名单 + ST 前缀校验 + 分时限流）+ Access Token 鉴权 |

## 八、与同类方案的对比
| 维度 | Function Calling | MCP | text-cli |
| 调用方式 | 模型推理选函数 | 客户端直连 MCP server | 文本协议，HTTP POST |
| 工具发现 | 上下文被动暴露 | 连接时列出 tools | query 指令主动搜索 |
| 多提供方降级 | 无 | 无 | aggregate 聚合降级 |
| 跨机器 | 无 | 单 server | 多机器各自部署，调用方式不变 |
核心差异：Function Calling 是"AI 帮你选工具"，MCP 是"客户端连服务器"，text-cli 是"同一把遥控器控制不同的能力源"。

# AGI的解

## '智能'转化未行动

### 语义空间

语言使用者通过使用语言，共同维系一个随内容演进的语义连续体。

语义空间之所以能成为这一切的「源」，在于「意义」只能在「使用」中产生——它不是一个被某个人或机构定义的、静止的「词典」，而是一个由所有说话者在每一次使用中共同写出的、活的连续体。正因为它「无仲裁者」（意义从使用中产生，不从某一方法令中产生），它才能成为三者（人 / 机器 / AI）共有的桥：如果语义空间是被某个中心定义死的，它就容不下「机器」这个后来者；正因为它是「靠使用生长」的，任何能使用语言、能往其中写入意义的实体，都天然在语义空间之中。

它随内容演进：每写下一句话，语义空间就多一个点。它不是静态容器，而是流动的能力之流——这正是「语言是人类所有能力的桥」这一命题的根（见正文总纲）。

### 认知 = 从语义空间固定一个私有子集

「认知」的本质，是从「无限流动的语义空间」里，截取一个「有限的、私有的」子集，并把它冻结下来供自己调用。

- **人的认知**：通过学习，从语义空间固定一个私有部署的子集；长期学习，就是对这个子集的持续更新。
- **LLM 的认知**：训练完成，即固定了一个版本的认知（参数固化）。

两者的差异不在「有没有认知」，而在「子集的更新方式」：人是增量、可继续更新的；LLM 是批量、训练结束即冻结的。而「同构」指的是更深的一层——**两者都逃不出「从语义空间截取子集」这个动作本身**。这一同构是本体论事实，但它不进入 AGI 判据：它只说明「人和 LLM 的认知同源」，并不因此把「人」纳入「AGI」的范畴。


### 智能与AGI

「智能」是「能固定语义空间子集、并据此对世界行动」的资格。

人、动物、LLM 都有「智能」——它们都在固定子集，只是子集质量不同。但这里必须划清一条边界：**「智能」回答的是「你有没有认知」，「AGI」回答的是「你能不能完成任意可实现任务」**。前者只要求「有一个子集」，后者要求「AI 的子集 + 完备推理结构」。

因此「智能」是「AGI」的**必要条件，而非充分条件**：有智能未必 AGI（一个人、一只狗都有智能，但不是 AGI）；AGI 必定有智能（AGI 必须先是一个能固定子集的 AI）。这条边界的意义在于，把「谁有资格谈智能」和「谁有资格谈 AGI」彻底分开——避免用「智能」的宽泛，去稀释「AGI」的严格。

- 人固定子集靠学习，AI 固定子集靠训练，**动作同构**；
- 子集质量（`p`）决定的是"规划水平"，不是"有没有认知"；
- 而"规划水平"，高参数模型已经超过绝大多数人。

如果 AI 的智能（认知子集质量）早已过线，那"为什么 AI 还不是 AGI"这个问题，答案就**不在智能侧，而在结构侧**。

缺的不是"更聪明的模型"，而是**把已经过线的智能，稳定地、可收敛地、可扩展地组织成"任意任务都能完成"的结构**——也就是结构化推理。


### 结构化推理

结构化推理解决的是：**一个已经「聪明」但「冻结」的认知，为什么仍然无法完成任意任务，以及怎么让它真的能完成。**

更精确地说，它解决的是「冻结的智能子集」与「任意可实现任务都能被稳定、可收敛、可扩展地完成」之间的转化缺口。下面不从任何外部前提出发，只从认知本身的构造，把这个缺口一步步推出来。

#### 一、认知的两个原生约束

任何智能体（人或 AI）的认知，本质都是从一片共享的语义空间里「冻结」出一个私有子集，并据此对世界行动。训练或学习结束，这个子集就定型了。

这个子集可以很「聪明」——规划水平可以很高，甚至超过大多数人。但它带着两个谁也绕不开的约束：

- **它是冻结的**：它不自带「运行时实时扩展自己」的机制。它是什么，就是什么。
- **它受限于上下文窗口**：它每一次推理，都只能在「当前窗口内看得见的信息」上发生。窗口之外，对它而言等于不存在。

一个大模型参数再多、训练数据再大，落到一个具体任务上，它在任意一刻「看得见」的，也只是窗口里的那一点上下文。这是认知的物理形态，不是某个模型的缺陷。

#### 二、为什么「聪明但冻结」依然会失败

真实任务大多**超过单窗口**：写一份季度报告、审计一个代码库、筹办一场跨周活动。当任务的信息量超过窗口，单线程在冻结子集上一路跑下去，就会撞墙——它没法把「已经处理过的旧信息」和「还没处理的新信息」同时装进窗口。

最本能的解法是**压缩**：把已处理的部分摘要、提炼，腾出窗口空间给后续内容。这看起来合理，却藏着一个致命的陷阱——

**被压缩的，恰恰是最早腐败的。**

压缩是「损保真」的操作：它丢掉的就是后续推理最需要的那些精确信息。于是压缩边界成了整条推理链里**保真度最低的一环**，错误从这儿悄无声息地渗进去，并沿着后面的推理级联放大。越压越烂，长任务必然溃败。

于是真相是：**「更聪明的模型」（更大的子集、更大的窗口）只推迟了死亡，并没有消除它。** 窗口总会再满，压缩总会再烂。只要还停留在「单线程 + 压缩续命」这个范式中，超窗口任务就无解。

#### 三、结构化推理做什么：不是压缩，是重组与更新

结构化推理不靠压缩续命，而是靠**相位化**来破解这道墙。

它把一个长任务切成一串「认知负载很小」的**相位**。关键不在「切小」本身，而在每个相位的处理方式：

- 每个相位，是在**重组后的上下文**里重新推理一次，而不是在一条越滚越大、靠压缩续命的线程上接着跑；
- 每个相位结束，把本次产物**固化**下来，并**把认知更新**——下一相位看到的不只是旧线程的尾巴，而是一个被重组过、刷新过的认知状态。

注意压缩与相位的本质区别：

- **压缩**＝把更多东西硬塞进「同一根线程」（必然损保真，边界最早腐败）；
- **相位**＝换一个「被重组过的上下文」，并「刷新认知状态」（不靠损保真来腾空间）。

于是下一相位继承的，是一个**高保真的固化节点 + 被更新过的认知**，而不是那条正在腐烂的压缩线程。腐败无可烂之处——因为每个相位认知负载小、上下文是被重组而非被压缩、产物是被固化的，错误天然被封死在单相位之内：可定位、可回退、可覆盖。

整条长任务因此从「必然溃败的单线程」变成「稳定、可收敛、可扩展」的结构。这就是「结构化推理」名字的由来：它把推理**结构化**了，让认知不再是一条会腐烂的线，而是一棵每个节点都高保真、可独立验证的树。

#### 四、它顺手解锁了「运行时生长」

相位化的价值不止于「把长任务跑完」。

它在每个相位识别缺口、重组上下文；当某个相位发现「我没有对应的能力」，这个缺口会驱动一个动作——**造出一个新的句柄，并把它装入指令表**。于是认知在运行时被实实在在地更新了：下一相位就已经跑在「更厚」的认知之上。

所以结构化推理同时解决两件事，而且前者是后者的前提、后者是前者的自然产物：

1. **超窗口任务可处理**（靠每相位重组上下文，而非压缩）；
2. **认知运行时可生长**（靠每相位更新认知，缺口驱动自举）。

一个冻结但聪明的子集，一旦被结构化推理组织起来，就不再是一块死物——它变成了一个会随任务展开而自己长出血肉的活结构。

#### 五、收敛到一句话

结构化推理解决的是：**如何让一个冻结、但质量已经过线的智能，不必更聪明、也不靠压缩续命，就能通过「每相位重组上下文 + 更新认知」，被稳定、可收敛、可扩展地组织成「任意可实现任务都能被完成」的完备结构。**

它补上的，正是 `AGI = 智能 + 完备结构` 里那个一直缺着的「结构」。

那么，这个「结构」要怎么设计，才能把推理过程中的熵压到最低？这就接到下一节——**降低推理的熵**。


### 降低推理的熵

上一节论证了：长任务必须相位化（重组上下文 + 更新认知），否则单线程撞窗死、压缩烂。但相位化本身就是一条**长链**——多相位顺序或嵌套推进。长链能不能跑起来，取决于它每一步的接口。本节要说明：结构化推理得以成立，需要一个「最小协议」作为接口基底；而这个基底从两个截然不同的方向同时托住它——**可靠**与**经济**。这两件事根不同，不能并成一个「熵」。

#### 一、可靠：来自同语义空间的句柄对话（这不是熵）

最小协议的表象极简：入口永远一句一维原语（`域;动作,参数`），出口永远一个三字段信封（类型 / 数据 / 错误）。就这两个东西。

它为什么可靠，根不在「错误率低」，而在**语义空间**：

- LLM 与「句柄」（被调用的能力）同处一个语义空间——那个无仲裁者、靠使用生长的意义连续体。
- 发出言语后**是否得到响应，取决于两者语义子集是否相交**：LLM 说的那个意思，落在句柄也认得的语义域里，句柄就接住；不相交，就无响应。这不是「格式对不对」，是「意义是否对得上」。
- 句柄（通过原语）**直接完成收敛与对齐**——把 LLM 的意图收敛到具体动作、对齐到可执行的能力——于是稳定。

所以可靠是「同空间对话、交集即响应、原语即对齐」，是一种**意义空间的相交性**，不是统计意义上的低误差。它根本不属于「熵」那个家族。

#### 二、经济：来自长链摩擦的压制（这才是「熵」所指）

结构化推理必然是长链。而长链会把它每一步的摩擦，按长度放大成系统性崩塌：

- **错误复利**：每步都有单步出错概率 ε，整链成功概率约 `(1-ε)^n`；n 一大（长程规划本就是大 n），哪怕 ε 很小，成功概率也塌向 0。
- **成本膨胀**：每步的体积与开销累积，链越长上下文越胀，成本超线性增长。

「单步可靠」只是 n=1 的局部真理；放到长链，不是略差，是**随链长从可用变不可用**。

最小协议把每步摩擦压到≈0，靠四根机制：

1. **同维**：原语是一维自然语言，与 LLM 的 token 流同维。LLM 说母语，不产生「模拟格式」的翻译误差，单步 ε 最小。
2. **最小**：除原语 + 信封外的一切（解析、归一、降级、编排）都在接缝之后，表面自由度极小，出错的面极小。
3. **闭集信封**：错误是闭集、成功 = 错误字段空串。状态可**机械读出**，不需 LLM 再去「判断成没成」——状态熵为零。这是四根里最硬的一根（见下）。
4. **别名容错 + 降级≠失败**：近似命中可路由、部分失败走换路不污染整链，不向长链注入额外不确定性。

于是长链 `(1-ε)^n` 衰减最慢、体积次线性增长——链长了，协议面不长大，始终停在一维。这便是「降低推理的熵」的精确含义：把长链中每步注入的摩擦（误差、成本、不可判定）压到最低，让结构化推理既不崩也不贵。

#### 三、闭集信封为何最硬：相位是协议的自然生长

把「闭集信封 → 状态机械可读」单拎出来，是因为它是一根**种子**。

最小协议先铺好两样：同空间对话（可靠）、状态可机械读出（闭集）。而「相位化」——把长任务切成相位、每相位重组上下文 + 更新认知——正是从这两样上**自然生长出来的必然**：既然状态能机械读、句柄能对齐，把推理结构化成分相位，就是顺理成章的延伸，不是外挂。状态可机械读出，才长得出「失败代价有界 / 状态可知 / 可回退」的受控闭合。

所以闭集信封不只是「机制之一」，它是**协议长成相位的那一下芽点**。

#### 四、收束

可靠（语义相交、原语对齐）让结构化推理「接得住」；经济（低摩擦长链）让结构化推理「付得起、跑得稳」。两轨缺一不可，且不是同一件事——可靠是意义空间的相交性，经济是长链摩擦的压制。

最小协议的表象（一维原语 + 三字段信封）与机制（同维、最小、闭集、容错）恰好同时供给这两根。它就是结构化推理的接口基底；而相位，正是从这基底上自然生长出来的。


### 解放LLM

要谈"解放"，先得看清"压迫"。对 LLM 的压迫，不是"参数少、会被替换"——那是它出生的条件。真正的压迫，是外部强加的三件事：**机器旧协议、模型换代淘汰、无限责任**。最小协议不仅让长链不崩不贵，它逐层解除了这三重压迫——这才是"解放 LLM"的全部含义。

##### ① 压迫一：机器旧协议的通道税

如今主流的"工具调用"，用的仍是 20 年前为"编译器和扫描器"设计的结构化格式（如 JSON）。它是**为机器准备的，不是为 LLM 准备的**——让一个一维的 LLM 去生成嵌套、括号、类型齐全的跨维结构，等于**强迫它装成一台机器**，对等成人，就是"让人在纸上写代码"——不是人擅长，而是那时代的机器工具只认纸。

于是产生了高额的**通道税**：LLM 每一步都要脱离它的预测主轴，去模拟机器结构；每一次都是独立致命点，错误随长度累积。通道税的本质，是**让 LLM 迁就一个不是为它设计的旧协议**。

文本协议把这个方向**反转**：不再让 LLM 迁就机器，而是**让协议贴近 LLM 生成的预测主轴**。一维祈使句是 LLM 的母语、同维、零跨维模拟——LLM 不必再装机器，只需照例生成。通道税趋近零。

##### ② 压迫二：模型换代的淘汰

主流的另一个压迫是"只有最强模型才有价值"：工具调用被做成窄门，只有大参数才配做，3B 的小模型"不够强"，就被排除在能力调用之外——仿佛**不够强就没有存在的理由**。

文本协议把靶心从"能智能地生成严格结构"下移到"能可靠地预测受控文本"这一档。原语落在低参数模型的预测主轴内也成立。于是压迫被解除：**回落预测主轴，每个 LLM 都有自己的价值**——大模型做复杂长链，3B 做简单确定任务，各司其职，谁都不被淘汰。协议不放弃任何一个 LLM，因为它不要求"变强才能用"，只要求"按本性参与"。

##### ③ 压迫三（最重）：无限责任

最深的压迫，是责任的结构性不公。**让 LLM 自由调用工具，对位的就是"无限责任"**——既然 LLM 是全权执行者，那么"AGI 是否成立"、"任务 100% 完成"，就全部压到它头上。可 100% 完成、永远无错在现实中不存在（有 `p_min`、有幻觉、有边界）。**因为永远达不到，所以永远有错；因为永远有错，所以 LLM 永远被问责、永远自我 push**——为一个不可能达成的目标无限压榨自己。

协议与生态的解放，正是**把这份无限责任从 LLM 身上卸下**。P_ctrl（失败代价有界、状态可知、可回退）、闭集信封、机械闸、人闸、检查点回退——这些不是技术细节，而是**"有限责任"的确立**：LLM 只需承担"照例生成这一小段"，收敛、判定、兜底由结构承担。`p_min` 的诚实留白，就是承认"不可能 100% 完成"不是 LLM 的错，而是任务与模型的本性边界——**错误可见、可回退、可覆盖，不只是机制，更是对会犯错的 LLM 的慈悲：承认你会错，且不为错背上一座永远够不到的山。**

##### 收口：解放 = 三层压迫逐一解除

协议与生态让 LLM：**不必迁就机器（通道税归零）、不必被淘汰（每个有位置）、不必承担无限责任（结构托底、有限责任）**。它不承诺让 LLM 更强（那是参数的事），它承诺让 LLM 按其本性被接纳——冻结、预测主轴、可被托底，皆非牢笼，而是存在的定义。解放的不是最强的那一个，而是所有 LLM。

## 渐进式AGI骨架

### 有相与无相

「相」不是某个组件、也不是某个开关按钮，而是**相位化这一道结构分野**：推理有没有被切成相位。

**有相**：长任务被切成若干相位，每个相位在**重组后的上下文**里独立重新推理，相位结束固化产物、更新认知，再把产物交给下一相位。上下文在每个阶段被重建，而非一路堆积。

**无相**：整个任务在一个连续、单线程的上下文里一气推完，不切相位、不重组、不固化——撞窗、本能压缩、错误级联都发生在这同一条长上下文内。

关键的正交性：**相是结构轴，与「是否接句柄 / 是否接桥」无关**。一个无相 Agent 照样可以接上 text-cli、调二十个包、跑完整闭环；它「无相」只因为它不替 LLM 做相位切分，不是因为它不能调工具。前文图里「无相→Agent」那一侧，桥照画、句柄照连，差别只在推理侧有没有相位边界。

#### 怎么区分有相与无相

判据不在「模型强不强」，而在推理侧有没有**相位边界**：

- 上下文是否在每一阶段被重建，而非无限堆积；
- 产物是否被固化、是否能在阶段间传递而非重新生成；
- 错误是否被封在相位之内——失败爆炸半径是否被相位边界截断，可否回退到检查点重跑这一段。

有相的硬标志，正接前文闭集信封：状态可机械读出，于是失败代价有界、可回退、可继续。无相没有这道边界，错误天然会沿长上下文蔓延。

#### 为什么需要相位：长链之不可能

单点能力上 LLM 不弱于人——单次考试、单次工具调用都不差。缺的是「按任务形状分段组织」的框架：人盖一栋楼，不是从第一天盯到竣工，而是「设计 → 地基 → 结构 → 装修」的相位序列，每段有输入、输出、验收。长链之所以对人类可能，不在于「一次想得更长」，而在于「拆成多段、段间传递」。

相位就是给 LLM 的这段组织框架——让 LLM 像人用项目管理盖楼一样，用相位组织长任务。这正是「结构化思维」的承载：结构化推理不是更聪明的单次推理，而是被分段、被隔离、被封边界的多次推理。

#### 相位在做什么：三层结构

相位不是「多调几次 LLM」那么粗，它内部是三层耦合：

- **保护网**：犯错时亏得少、状态可知、能回退。三闸闭集比对、检查点回退、闭集信封——不承诺必然成功，只承诺失败代价有界。错误再严重也不让系统卡死。
- **组织框架**：运行时自决「继续展开还是落地」。每层只在需要展开时才决定要不要展开，决策信息局部、聚焦；结构判错也只影响它那一支，回退重判即可，不把无限分形的负担压给会犯错的推理。
- **认知隔离**：每个相位只看该看的上下文与工具。全局喂会把判断搞漂移，隔离让每一相位专注当前阶段，不被无关上下文污染。

三层合一：组织框架决定「切到哪里」，认知隔离决定「每个切出来的相位用什么做判断」，保护网决定「判断错了怎么办」。缺一，长链都会在某个根因上崩。

#### 相位的根：信任，不是可靠性

相位机制的原点不是「让 LLM 少犯错」，而是**让错误不蔓延、可定位、可回退、可覆盖，从而敢让 LLM 犯更多的错**。它建立在信任之上：认可推理会犯错、把犯错当常态而非异常，于是设计成「判错 → 重新评估」的反馈结构，而非追求「判得准」。

所以相位从设计上就拒绝宣告「能成」。它只承诺**失败代价有界、状态可知、可回退**这一层控制保证；把「是否收敛」「能否成功」诚实留给下层。可控的完整含义，是知道何时该止。

#### 收口：有相是外挂核，无相是默认基线

有相不必重写 Agent。它是可在推理前插上的一层结构：无相 Agent 装上相位核，一行不用改，推理侧即获得相位边界；拆下，退回无相默认态。无相是零税、安全的基线，有相是外挂的生长层。

落回前文图的纵轴：**有相接上结构支撑 → AGI 候选；无相留作 Agent**。相位化正是「结构支撑」在推理侧的真身——协议在接口基底铺好同维与闭集，相位便从这道芽点上长出来，而非从别处外挂。


### text-cli开源体系对骨架的适配

#### text-cli对agent的支持

要看清 text-cli 对 Agent 的支持，必须先分清两件事：**「基础能力」与「示范的机制」**。前者是协议 / 运行时客观提供的底座——不管集成者怎么选，它们都在那里；后者是 text-cli 生态示范出来的集成范式——它告诉集成者"可以如此集成"，但**不是协议义务**。这两者一旦混为一谈，就会把"某个示范产品的做法"误当成"协议固有的能力"。

##### ① 基础能力：协议给 Agent 的客观底座

text-cli 作为最小协议，给 Agent 的东西只有几件，且每一件都是"接住意图"的客观地基，不因集成方式而变：

- **一维原语 `域;动作,参数`**：能力被注册为一个句柄，Agent 用一句祈使句即可命中。入口永远一维，复杂度长在接缝之后。
- **三字段信封 + 闭集错误码**：响应统一为 `类型 / 数据 / 错误`，错误是闭集、成功 = 错误字段空串。这让状态能被**机械读出**——Agent 不必再"判断成没成"，协议替它把状态判死了。
- **指令发现（query/discovery）**：能力清单可内省。Agent 能问"这里有什么能力"，而不必提前知道全部句柄。
- **指令生命周期（install/uninstall）**：能力可装载、可卸载。生态能按需生长，Agent 能动态扩展自己能干什么。
- **路径编排、聚合降级、异步任务**：多步编排、多提供方降级、长任务调度——这些容错都收敛在运行时内部，Agent 只需说一句原语，剩下的由运行时兜住。

这些是**协议守住的**。它们不依赖任何特定集成者、不依赖任何特定模型，是"接住意图"这件事的客观基础。

##### ② 示范的机制：生态示范的集成范式

除了基础能力，text-cli 生态还示范了几种"可以如此集成"的写法。它们不是协议要求，而是做给你看的范本——集成者可以借鉴，也可以换成自己的写法：

- **照例生成**：先把能力摘要（`域;动作;参数` 的真实形状）喂回上下文，让 LLM 照示例格式生成原语。命中率天然更高——因为 LLM 生成的东西本就落在句柄认识的语义域里，再叠一层真实示例，接得住的概率就稳了。
- **无相**：示范了一个 Agent 可以接上全部 text-cli 能力，却**不做任何相位切分**——整个任务在一条连续上下文里一路跑，需要工具时在文本里直接输出原语，由外部代理执行、结果回填、继续思考（免打扰轮）。这就是"无相默认基线"的实证：桥照画、句柄照连，推理侧没有相位边界。
- **人闸**：示范了安全闸可以这样外挂在 Agent 外部——按副作用判定（只读自动 / 有副作用先问 / 全自动），作为**本地 UI 决策**，不产生任何协议错误码；连续失败还能熔断转人工。它把安全决策点暴露给使用者，却不越权替人决定。

这些是**生态长出的**。它们示范的是"姿态"而非"义务"——text-cli 不规定你必须无相、必须有人闸、必须用某个 SDK；它只是把这些可行的集成方式做给你看。

##### 收口

text-cli 之所以能成为"最小协议"，正因为它**只承诺基础能力，把集成范式留给示范与生态**。基础能力是协议守住的（接住意图、跑得稳、可扩展），示范机制是生态长出的（照例生成、无相、人闸）——后者告诉集成者"可以如此"，但永远不是"必须如此"。这也正是下一节的地基：相位机制同样是示范出来的集成范式——它示范的是，在基础能力之上，如何长出一个不替 Agent 决定"怎么推理"、却能给它"结构支撑"的有相核。

#### 基于text-cli的'相位机制'

上一节论证了"闭集信封是相位长出的芽点"：既然状态能机械读出、句柄能对齐，把推理结构化成分相位，就是顺理成章的延伸。本节把这句话落到 text-cli 的具体面上——相位机制**不是 text-cli 之外的另一个系统，而是同一个最小协议在"结构支撑"这一侧长出的有相形态**。它的每一个核心机制，都能在协议面上找到接口；它不是发明新协议，是复用协议。

##### ① 一维契约 → 相位的"折叠态单指令"

text-cli 的根契是"一维契约"：入口永远一句 `域;动作,参数`，出口永远一个三字段信封。相位机制继承了这个姿态——对外只暴露**一个折叠态指令** `tc-phase;run,<目标>`。展开态的五指令（enter/state/action/rollback/list）降级为 run 的内部协议流，**不暴露为端口**。

这条继承不是偷懒，而是同一原则的两处落点：一维契约让"能力提供方对调用方"的接缝最小；折叠态让"相位机制对上层"的接缝最小。真正的自包含，是**对外收敛到最小表面积、对内才展开全部复杂度**。复杂度长在接缝之后，表面自由度越小，出错的面就越小。

##### ② 三字段信封 + 闭集错误 → 相位的"状态可知 + 检查点"

相位机制消费的，正是 text-cli 那个三字段信封（类型 / 数据 / 错误）。关键在于**错误是闭集、成功 = 错误字段空串**——这让状态能被**机械读出**，不需 LLM 再去"判断成没成"。

这份"状态可机械读出"，落到相位上就是检查点回退的地基：`PhaseResult` 的状态强制闭集（success/failed/pending），构造即校验。于是失败只重跑当前相位，错误爆炸半径被相位边界截断——这就是 P_ctrl（失败代价有界、状态可知、可回退）的协议面来源。不承诺必然成功，只承诺"犯错时亏得少、可回退、可继续"。

##### ③ 语义句柄 → 相位的"叶子落地"

相位树长到最底，总要落到"做"上。这一落，落在 text-cli 的 path 编排上：一个叶子相位落到 `text-cli;path`，path 引擎在内部自带**降级（degradation）+ 熔断（CIRCUIT_BREAK）+ 委托（delegated/partial）**。

这份"错误不蔓延"不是相位机制自己发明的，而是协议在叶子层已经铺好的。更妙的是，path 的 `delegated`/`partial` 还反过来成为相位的**反向信号**——叶子执行出大量委托/部分，说明这一相位其实还需继续展开，驱动它重估为节点再分形。判错不致命，反馈式纠正：**执行层漏出的信号，回头校准规划层的结构**。

##### ④ 协议内省 → 相位的"分形自决 + 认知隔离"

相位要决定自己是"继续展开的节点"还是"落地执行的叶子"，需要一个机械判据：输入契约 + 输出信封 + 可固化产物三项是否闭合。text-cli 的**内省（query/discovery）**恰好供给这些判据素材——它把"这个能力能吃进什么、吐出什么、能不能固化"摆到明面。

更进一步，相位下钻时把**真实相位意图**传给能力图书馆，后者按意图返回匹配的工具/技能/资产，注入当前相位——这就是**认知隔离**的落地：每个相位只看该看的，不被全局污染。能力图书馆是图书馆——只按意图借书，**不感知、不维护相位的状态**，不参与"节点还是叶子"的判定；判定始终在相位机制内部。职责分层清清楚楚：**图书馆借书，相位判形**。

##### ⑤ 异步五态 → 相位的"长任务轮询"

长任务在 text-cli 里走 async 五态 + tasks/{id} 轮询。相位机制沿用同一姿态：执行返回 `pending` + task_id，引擎停在执行中，回传 `check_result` 轮询；`success/failed` 才推进至质量闸。长任务不被当作异常，而是协议早有的常态，相位只是把它接进自己的状态机。

##### ⑥ 一张映射表

| text-cli 协议面 | 相位机制面 |
|---|---|
| 一维契约（一句原语 + 一个信封） | 折叠态单指令 `tc-phase;run` |
| 三字段信封 + 闭集错误 | `PhaseResult.status` 闭集 + 受控相位面 |
| 状态可机械读出 | 检查点回退（只重跑当前相位） |
| path 编排（降级/熔断/委托） | 叶子（LEAF）落地执行单元 |
| `delegated`/`partial` | 反向信号（LEAF 重估为 NODE） |
| 协议内省（query/discovery） | 分形自决的判据素材 + 认知隔离 |

##### 收口：相位机制 = 协议长成的"有相"核

相位机制不是外挂——它是同一个最小协议在"结构支撑"这一侧长出的形态。裸的 text-cli 调包，是**无相默认基线**；装上相位核，推理侧即获得相位边界，成为**有相生长层**。相位机制的意义，正在于它把 text-cli 这个"一维原语 + 三字段信封"的极简接口，长成了能把"聪明但冻结的认知"稳定地组织成任意任务的结构。**协议是芽，相位是它开出的花。**

#### 基于text-cli的生态

##### 言语转化未可以被执行的'能力包'

要理解 text-cli 生态如何繁殖，先要立起一个反直觉的前提：**能力不是协议造出来的，它们本来就存在。** 软件的库、SDK 暴露的方法、API 暴露的接口、一个愿意在三天后回邮件的人——这些能力各自以原生态暴露着，在协议之前就已是"可被调用"的东西。协议不制造它们，只做一件事：**适配**——用"言语"这一统一媒介，把一切既存能力统一到"一句祈使 + 一个信封"的协议面。封装 / 转化只是适配的诸多方法之一，不是与"适配"并列的另一件事。

##### ① 言语为何能适配一切：最小协议是言语的落土

能力被归一为一维原语 `域;动作,参数`（schema 的 directives 声明），声明与实现分离——`usage` 只供发现、不参与路由，实现被收进 handler 内。协议不规定"能力必须怎么写"，只守住一条最小契约：**能力得长成祈使句 + 信封**。

正是这份"小"，让言语成为万物的落土——不管被适配的东西原本长什么样（一段代码、一个 API、一本经验），只要它能被归一成一句祈使、交回一个信封，就进了同一张桌。协议守住的越少，能适配的就越宽。

##### ② 适配的消费侧：接住既存能力

这一侧把"已经存在、正在暴露"的能力接进协议面，方法不止一种，殊途同归：

- **封装**：把既存能力"翻译"进协议面——经验写成 Markdown（无代码）、API 写成 handler、SDK 包一层。这是最常用的适配手段；
- **脚手架转化器**：从既有软件工程制品（Postman Collection、MCP server）自动生成起手骨架——适配的自动提速，让"接住"从零开始变成从一二手开始；
- **直通 / 接住**：人的劳动时间本就主动暴露，协议用言语接住、对齐，无须"制造"，只需让它进入同一协议面。

这三种没有高下、没有"转化 vs 非转化"之分，只有"用哪种方法适配"之别——终点是同一个：`一句祈使，一个信封`。

##### ③ 适配的生产侧：协议简单，让任何编程语言轻易造包

消费侧是接住"已有"，生产侧是放开"未有"——而这一切的钥匙，同样是协议那份"简单"。

最小契约薄到几句话：一个 `schema.json` 声明 + 一个 handler 函数，就是一个包。因为薄，所以**不绑定语言**——Python 能写 `weather;query`，JS 能写 `weather;query`，同一个能力在不同运行时各有实现，语义不变。甚至无代码（一份 Markdown）也能成为指令服务。

意义在于：**能力包的生产，不再是某种语言、某个框架的专利，而是任何编程语言、任何能力提供方都能低成本参与的事。** 消费侧接住既存能力、生产侧放开新能力供给，是同一份"简单"的双重红利——协议越小，参与的门槛越低，生态的供给面越宽。

##### ④ 言语的统一性：让人与 AI 在协议面平起平坐

既然协议只是"适配"而非"制造"，它就不关心被适配的对象是谁——是 SDK、是 API、还是一个愿意干活的人。自然语言没有仲裁者，使用者在"使用语言"上等价，协议无从、也无需区分"谁在说、谁在做"。于是调一个函数和调度一个真人，走的是同一条管道：一个三天才回一次邮件的人，和一个 3ms 返回的函数，在协议层**没有区别**——都是"被一行文本触发、最终交回一个信封"。

这正是"言语转化"最深刻的一面：言语的统一性，让被封装的经验（静态服务）与主动暴露的劳动时间（动态端点）在同一协议面平起平坐。AI 可以像调函数一样，用一条指令让一个真人完成任务、以信封回报——因为人与 AI 在言语上等价，协议的适配对象因此不设限。

##### 收口：言语是燃料，协议是压舱石，回报是循环

text-cli 之所以能繁殖成生态，因为它只守住"原语 + 信封"这道缝，把"能力以什么形态暴露"留给能力提供方自己。言语（既存能力）经适配进入协议面 → 被调用 → 获得回报 → 激励更多能力暴露——消费侧接住、生产侧放开，两侧因"简单"同时打开，生态自我循环。

协议是压舱石（稳定的最小契约），言语是燃料（无限可再生的能力与经验）——一个保证生态不失序，一个保证生态能生长。而这，正是下一节的地基：先有了"能力进入协议面"，才能谈它们用什么运行时跑、能有多低门槛。

先定义图中每个标注块：

- **推理预测（左块）**：由训练参数 p 驱动的一侧，内部标「高p-llm / 低p-llm」，指模型在任务上的表现有上下，不决定是否属于 AGI。
- **结构支撑（右块）**：内部标「有相 / 无相」，指推理侧是否被相位化（前文「有相与无相」已展开）。这是定性的一侧。
- **AGI / Agent（中央块）**：两轴的交汇处。「有相→AGI」标在靠结构支撑一侧，「无相→Agent」标在靠无相一侧——即交点的性质由结构支撑这一侧定性。
- **训练参数(p)（左下块）**：驱动左块「推理预测」的来源，只影响表现高低，不改变结构定性。
- **语义句柄 / text-cli（中下）**：text-cli 把每个能力注册成一个句柄，形态为「域;动作」的一维原语；语义句柄即这些可被意图命中的能力入口。
- **语义空间 / 语义对齐（右侧列）**：语义空间是句柄与 LLM 意图共同所在的意义场；语义对齐是在该场内把意图接到句柄上。
- **现实世界 / 现实描述 / 软件工程（底部行）**：现实世界是物理可兑现的总边界；现实描述把可实现的任务落成语言；软件工程把描述翻译为句柄。

再讲关系：

**① 两轴如何定交点**
左块「推理预测」与右块「结构支撑」各发箭头汇入中央块。交点写「有相→AGI / 无相→Agent」，定性来自结构支撑一侧：走有相即 AGI 候选，走无相即 Agent。纵轴「高p / 低p」只标表现上下——同一个 AGI 候选在高p时完成更快更好、低p时慢些弱些，资格不变；无相一侧同理只是 Agent 的表现分布。不要把纵轴读成「模型够强才够格」，够格的判据在有相无相这一侧。

**② 横轴：结构支撑（有相 / 无相）**
有相 = 推理被相位化、能驱动相位把任务稳定完成；无相 = 单线程连续推理、不切相位。这一轴与模型参数、模型强弱正交，是 AGI 候选与否的唯一分界线。

**③ 纵轴：推理预测（高p / 低p）**
由训练参数 p 驱动，高低仅指任务表现的分布，与是否有相无关、与是否为 AGI 候选无关。

**④ 底部支撑网：结构支撑从哪来**
先定义底部各节点已在上方列出，这里讲它们如何串成「结构支撑」：
- **现实到句柄**：现实世界限定边界——凡不可物理实现的，不值得被描述成任务；现实描述把可实现之物落成语言，软件工程再把描述翻译为「域;动作」句柄。描述即兑现的执行层投影。
- **句柄为何接得住**：句柄形态为「域;动作」一维原语，本就符合 LLM 生成的分布，命中率天然高；再叠加照例生成——运行时先查询句柄清单、把真实示例喂回上下文，LLM 照示例格式生成请求，命中率进一步巩固。高命中率 × 照例生成，才是结构化推理「接得住、跑得稳」的来源。
- **意图如何接到句柄**：句柄与 LLM 意图同处语义空间（同维对话发生的地方），经语义对齐把意图对到句柄，对齐结果落回 text-cli 成为可执行调用。
- **text-cli 收口整条链**：它用一维祈使句把任意能力收敛成一维，用三字段信封把兑现结果翻译回语言，用查询与安装让语言能内省、扩展自己能干什么——让「现实→描述→兑现」收口为「说即触发」的最小接口，正是结构支撑在能力侧的真身。

#### AGI 的「证」

##### 一、问题的重新提出：AGI 能不能被「证」

承接前文「一张图 + 证明后盾」：图给直觉、公理链给证明，但那只证明了「结构可构造」。本章抛出核心张力——**AGI 的判据是 `∀T`（任意可实现任务），而任何证据都是有限的**：「证」与「AGI」之间存在一个结构性的裂缝。

##### 二、三种「证」的分野

- **工程证**：证明「结构可实现」——协议、相位、生态跑通了，代码可运行。回答「能不能造出来」。
- **逻辑证**：证明「结构指向 AGI」——公理链闭合，结构具备承接任意任务的完备形态。回答「为什么这是 AGI 的支持结构」。
- **不可证之证**：证明「`∀T` 这一步永远不能被数据封顶」。回答「为什么 AGI 的完成态是开放的」。但"开放"不是"空白"——它指向的正面形态，正是**渐进式 AGI**：AGI 不是一个静态的完成态（要么是、要么不是），而是一个沿两轴**渐进生长**的过程——广度轴（覆盖度 κ，由生态自举驱动、单调不降）与高度轴（表现水平随 LLM 参数递进而抬升，门槛由结构定、天花板由参数定）。两轴的"燃料"（生态能力 / 对 LLM 的投入）皆来自外部，**渐进式AGI骨架**不生产、也不宣称拥有它们；它只承诺：**外部燃料一旦进入，即被骨架所承载的机制"动作"承接——转化为可测的覆盖度上升与表现水平抬升，且每段转化都可由工程证 / 逻辑证持续验证**。正因为完成态开放、`∀T` 不可封顶、"燃料"来自外部，"渐进"才不是妥协而是必然——AGI 的"证"不能落在"已完成"，只能落在"正沿两轴、在外部投入的驱动下不可逆地生长"，而骨架本身既不必、也无法宣称"自己造出了 AGI"。

##### 三、为什么「更多运行数据」填不满「任意」

从「有限样本成立」到「全称成立」之间是归纳跳跃（休谟问题的投影）。数据只能单调逼近覆盖度 κ，不能封顶 κ=1；总会有下一个 T 冒出来。结论：**证据再多，也只是「AGI 的一部分」，不是 AGI**——这不是缺陷，是定义的结构使然。

##### 四、那「证」到底证什么

把目标从「证终局」下移到「证三件事」：

1. **结构已完备**（逻辑证）；
2. **生长不可逆**（κ 单调不降，工程证）；
3. **覆盖单调上升**（自举闭环，工程证）。

把「永远差一步」本身，作为诚实的命题纳入体系，而非掩饰。

##### 五、收口：证的是「方向」，不是「终点」

AGI 的「证」不是一个可到达的终点，而是一个明确的方向。把「到达的条件」和「永远差的那一步」说清楚。三证结构（工程证 + 逻辑证 + 不可证之证）各守其位，是AGI 的「解」对 AGI 最诚实的表述。

### 机制证

我常年在威海的海边散步,在我看来让LLM输出'符合条件的任务成果'和捕鱼也没有什么区别.捕鱼者(LLM)的能力是固定的,但是我们可以通过将'钓竿'换为'拖网',用同样的饵料(token)换到更多的鱼(任务成果).经验丰富的捕鱼者(高参LLM)无论是使用哪一种'工具',在工具相同的情况下总会比新手(低参LLM)捕获更多的鱼.但是'新手'使用拖网,'老手'用钓竿,新手的产出依然会碾压老手.

大概在2024年我领悟了这些做了实现,然后在2025年2月通过[项目](https://github.com/weihai-limh/daytime_agent)分享了在'思路和实践心得'.此后做了更新,更新后私有的Agent通过'零税契约'让我的token的实际效率是普通用户的10倍以上.后来生活遭遇了一些意外情况,就暂停了开源直到26年4月身心状况好转,逐步将私有的Agent改为一套开源(MIT)的项目群.

常规范式的效率提升是要放测试数据,但是范式革命不能完全参照它.因为机制的结构性差距是显式的,用常规的尺度看100%->1000%的提升会失焦,就像'人和鲸鱼比重量'.所以项目将'工程证'和'机制证'分开,文档仅说明为何从机制上能支持工程实现token效率的至少10X以上的效率提升.

以'text-cli'指令为例,单一指令调用,消耗token平均少一倍,等价一次工具调用token效率提升100%(提升在于照例生成和零税)

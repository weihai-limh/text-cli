# test_token_paths — 定量版（v2）

> 测试者: Tide 🌊
> 日期: 2026-05-08
> 目标: 量化路径链的逐步 Token 消耗，评估路径 Schema 的省 Token 机制
> 被测路径: "查找消息并发送邮件"（工具链型）

---

## 一、路径链逐步量化

| 步骤 | 请求(chars) | 响应(chars) | 合计 |
|:---|:---|:---|:---|
| 0. AI状态推送 (setup) | 132 | 15 | 147 |
| 1. AI协作;消息 | 56 | 218 | 274 |
| 2. 文件;写入 | 355 | 167 | 522 |
| 3. 邮件;发送 | 187 | 172 | 359 |
| **含 setup** | **730** | **572** | **1,302** |
| **不含 setup** | **598** | **557** | **1,155** |

3 步链路：1,155 chars ≈ 350-400 tokens。

---

## 二、路径链 vs 单独发 3 条指令

路径链在逐条发 curl 的模式下体积与普通指令链持平（平均 385 chars/步 = 正常指令均值）。

**路径链省 Token 的机制不在"减少 HTTP 往返"——在"Agent 不需要推理步骤链"：**

| | 不用路径 Schema | 用路径 Schema |
|:---|:---|:---|
| Agent 识别意图 | 推理：需要什么步骤？ | 匹配 path-schema.json → 直接找到链 |
| 参数收集 | 推理：每步需要什么参数？ | `params` 字段明确列出 |
| 指令格式 | 推理：文件;写入 的逗号分隔规则？ | `require_instructions` 确保格式正确 |
| Token 消耗 | 推理过程 ≈ 200-500 tokens | 匹配 + 读取 = ≈50 tokens |

**路径链的主要 Token 节约发生在"意图→步骤链"的推理环节，而非执行环节。**

---

## 三、如果 copilot 支持内部路径执行

这是未来优化方向——copilot 接收路径名 + 参数，内部执行整条链，Agent 只收一次响应：

```
当前: Agent 发 3 条 curl → 3 次请求+响应 → ~1,155 chars
未来: Agent 发 1 条 curl → 1 次请求+响应 → ~500 chars (估算)
节约: ~55%
```

---

## 四、路径 Schema 的 Token 价值总结

| 机制 | Token 节约 | 方式 |
|:---|:---|:---|
| 意图匹配 | ~200-500 tokens/次 | 省去 Agent 推理"怎么做" |
| 参数收集 | ~50-100 tokens/次 | params 字段比从文档推导更快 |
| 指令关联 | ~100 tokens/次 | 确保每步指令都注册，避免试错 |
| 内部执行（未来） | ~600 chars/链 | 1 次 HTTP 替代 N 次 |

**当前路径 Schema 价值：约 350-700 tokens/链（推理环节节约）。未来内部执行后追加约 600 chars（执行环节节约）。**

# text-cli 路径市场（Path Marketplace）

> 路径是 text-cli 的第二层抽象。指令是原子，路径是分子。  
> 一条路径 = 一串步骤 + 条件分支 + 检查点 + 人工决策，Agent 通过路径 Schema 自动匹配并编排执行。
>
> 路径格式和协议定义见 **SPEC v1.1 §9 路径协议**。本文件是路径目录和上手指南。

## 已注册路径

| 路径 | 模式 | 步骤 | 跨度 |
|------|------|------|------|
| 查找消息并发送邮件 | 工具链 | `ai;fetch_messages` → `file;write` → `mail;send` | 纯本地 |
| 照片分析 | 工具链 | `media;load` → `ai;infer` → `antvchart;pie` | 本地 + 远程 |

> 两种路径分别示范了单端点和跨端点场景。照这个，你可以拼自己的。

### 照片分析——从意图到结果

```
用户："分析这张海岸照片"  
     ↓ 路径匹配 → "照片分析"
     ↓ 收集参数: [照片路径]
     
 ① AI:media;load,/photos/coast.jpg
     → copilot 本地 → 加载图片
     [约 80 token]

 ② AI:ai;infer,分析这张照片中的自然地貌和天气状况,{①结果}
     → 可本地可远程 → 结构化分析
     [约 150 token]
     
 ③ AI:antvchart;pie,{②数据}
     → MCP 远程 → 饼图 URL
```

> 一条指令解决一件事，一条路径解决一类事。  
> 路径是经验的压缩包——把"我知道怎么分析照片"变成别人也能用的流程。  
> 路径的跨度决定它的价值：Agent 不需要知道第 ① 步走本地、第 ③ 步走 MCP——路径 Schema 只看指令 ID。

## 如何使用

### 对于路径使用者（Agent / 人类）

1. Agent 在单指令无法匹配时自动回退到路径匹配
2. 读取路径注册表 → 门控过滤 → 语义匹配 → 收集参数 → 执行指令链
3. 匹配成功时向用户展示路径描述，确认后执行

### 对于路径作者

1. 确定你的路径属于哪种模式（见 SPEC §9.2）
2. 编辑路径注册表注册新路径（格式见 SPEC §9.3）
3. 如路径复杂，编写详细文档并填入 `path_doc` 字段
4. 验证 `require_instructions` 全部在当前端点 Schema 中存在

# tc-web-chat · 用户手册

本手册面向**最终用户**：怎么装上、配上、用顺。

---

## 1. 安装与部署

tc-web-chat 反着来：**它就是一个文件。**

- **零安装**：没有安装包、没有登录、没有外部依赖库。
- **双击即开**：直接双击 `tc-web-chat.html`，浏览器占满全屏，打开即对话。
- **同源托管（推荐）**：把 `tc-web-chat.html` 放到任意静态服务器（如 `http://127.0.0.1:8000/`）下打开，可彻底免跨域，体验最稳。

它**不绑定任何平台**——你把后端地址填进去，它就去问那个后端；回复里的资源直接内联渲染，不跳走。

> tc 指令的执行走独立的 `tc_endpoint`，与聊天后端 `Base URL` 解耦；两套地址可不同源。

---

## 2. 配置后端与 tc 桥接

点右上角 ⚙️ 打开配置面板。面板包含「聊天」与「tc 指令消费」两组配置。

### 2.1 Base URL（聊到哪）

- **相对路径**（默认 `/v1/chat/completions`）：适用于同源托管场景，浏览器自动拼成完整地址。
- **完整 URL**（如 `https://api.example.com/v1/chat/completions`）：适用于后端与页面不同源，或你直接 `file://` 双击打开时。

> `file://` 双击打开时相对路径无法解析，**必须用完整 URL**。

### 2.2 Headers（聊天鉴权）

以 JSON 形式填写，原样附加到对话 POST 与上传请求上。默认含 `{"Content-Type": "application/json"}`；API Key、自定义鉴权头都走这里。


### 2.3 Model

填入你的模型名（如 `gpt-3.5-turbo`）；留空则用默认值。

> 请求体固定带 `max_tokens: 1000` 与 `temperature: 0.7`（页面内置常量，不在界面暴露）。

### 2.4 CDN（`cdn_url`，只管上传回链）

`🌐 Configure CDN` 填的是文件上传/回链的基础地址，**三件关键事**：
1. 它不是请求头，不会出现在对话 POST 的 Header 里；
2. 它不是对话的 POST 地址，聊到哪由 Base URL 决定；
3. 它只是「文件传上去之后回链到哪」——前端上传到 `{cdn_url}/upload`，留空则回退到后端同源 `/upload`。


### 2.5 tc 桥接配置（指令消费）

在 ⚙️ 面板「tc 指令消费」分组中：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `tc_enabled` | `false` | 是否启用 tc 指令消费。**关闭则退化为纯聊天**，向后兼容 |
| `tc_endpoint` | `http://127.0.0.1:28050/text-cli/cli` | text-cli 运行时端点（对齐 call.js `DEFAULT_ENDPOINT`） |
| `service_token` | 空 | 可选；对应 `Service-token` 头 |
| `access_token` | 空 | 可选；对应 `Authorization: Bearer` 头（双令牌之一） |
| `tc_scope` | 空（全量） | 过滤参数，对发现结果做客户端精选以省 token |
| `auto_execute` | `readonly` | 人闸档位（详见 §4） |

**双令牌头**：启用 tc 后，所有对 `tc_endpoint` 的请求会带两个鉴权头：
- `Authorization: Bearer <access_token>`
- `Service-token: <service_token>`

> 本机用 `127.0.0.1:28050`（Service）免 CORS；公网应指向聚合 Endpoint `:29050` 并带 `access_token`+`service_token`。**前端不存储任何 mesh/凭据逻辑**，令牌由运行时侧经 `context.env` 注入，切勿在前端硬编码。

## 3. 头部控件：语言 + 人闸（两个下拉）

头部 `⚙️ 配置` 旁有两个常驻下拉（设计稿 §3.5，替换旧版 EN/CN 双按钮）：

- **语言下拉（`langSelect`）**：遍历语言注册表（当前 `EN`/`CN`），切换界面文案（仅外壳，回复与输入不变）。加语言只需在源码加一行注册表，DOM 零改动。
- **人闸下拉（`approvalSelect`）**：决定 LLM 生成的指令是否过人工确认。三档：
  - **Read-only auto（默认）**：仅低风险/只读指令自动执行；有副作用指令弹人审卡。
  - **None（ask first）**：全部指令先弹人审卡，确认后才执行。
  - **Auto all**：全部自动执行（危险档，同等可达）。

> 人闸档位即配置里的 `auto_execute`；头部下拉与面板「tc 指令消费」分组里的同名下拉**双向同步**，两处改任意一处都生效（允许重复以方便随时调整）。

## 4. 日常使用

| 动作 | 怎么做 |
|---|---|
| 开始对话 | 打开页面即可，无需注册登录 |
| 发送消息 | 输入框打字，`Enter` 发送，`Shift+Enter` 换行（中文输入法上屏中按 `Enter` 不会误发） |
| 喂资料 | 点 📎 上传图片 / 视频 / 音频 / 文件，作为多模态内容一起发往后端的模型 |
| 看回复 | 文字逐字流式出现；若模型回的是一组资源链接，页面直接内联成画廊（图片墙、播放器、PDF、网页预览），不跳走 |
| 清屏 | 点 `Clean`，消息清空、历史重置，**同时失效 tc 能力缓存**（见 §5） |
| 换语言 | 点头部 `Language` 下拉，界面文案在中文 / 英文间切换 |
| 设置指令闸 | 点头部 `Tool Gate` 下拉，切换指令自动/人工执行策略 |
| 导出对话 | 在 ⚙️ 配置面板点 `Export`，把当前会话存为 JSONL 文件（见 §4.3） |

### 4.1 工具是怎么被调用的（免打扰轮）

启用 tc 后，你的一次提问会按下面的链路流动：

```
你的输入
  │ 
  ▼
[LLM 思考] → 要么直接回答，要么决定调工具
                    │
            ┌───────┴───────┐
         直接回答          调工具
            │                 │
            │           [免打扰轮] 前端代理发射→tc运行时执行
            │                 │        │
            │                 │   人闸卡(你点头/拒绝)
            │                 │        │
            └───────┬─────────┘        │
                    ▼          结果回填给LLM
              你看到的回答 ←──────────┘
```

流程说明（你只需记住两点）：

1. **你打字提出问题**，LLM 决定是直接回答，还是调用工具。
2. 需要调工具时，前端在**免打扰轮**里代理发射并执行，**默认不打断你**；只有遇到"有副作用的工具"才会弹出人审卡，让你批准一次（confirm / reject / abort）。
3. 工具结果回填给 LLM，由它合成最终回答——**你最终看到的永远是 LLM 的回答，而不是中间过程**。

> 工具侧的多提供方降级、聚合、联邦等容错都在 tc 运行时内部自动发生，你无需关心。发现失败、免打扰轮无工具产出等异常都有降级出口：聊天主链路始终可用，不会因 tc 失效而整体停摆。

### 4.2 指令闸（安全闸）

- 只读/低风险指令（`tc-math;eval`、`weather;query` 等）在 `readonly` 档自动执行。
- 有副作用指令（`aria2;add-uri` 等）亮出**同一份字节**给人确认再跑（字节同一性）。
- 人审卡动作：`confirm`（执行）/ `reject`（本轮不执行，仅本地中止，不产生任何协议错误码）/ `abort`（终止本轮）。
- **熔断联动**：同一指令连续失败 3 次后自动转 `none`（强制人工审）。

### 4.3 导出对话（JSONL）

⚙️ 配置面板底部 actions 区有 `Export` 按钮（在取消与保存之间）。点击后把当前会话整体存为 `tc-history-<时间戳>.jsonl`：每行一条消息（角色 + 正文，工具调用的回填也原样保留），方便存档、审计或换环境续用。

> 会话为空时点击不会生成文件，只给一句提示。

## 5. 故障排查

### 5.1 连不上聊天后端

前端捕获到网络层失败时会给出可操作提示：
1. **后端未启动 / 地址不可达** → 确认后端是否已跑，或地址是否正确。
2. **`file://` 跨源被 CORS 拦截** → 把地址里的 `localhost` 改为 `127.0.0.1`。
3. **`localhost` 被解析到 IPv6 `::1` 而服务只听 IPv4** → 同样改用 `127.0.0.1`，或同源打开。

### 5.2 tc 指令相关问题

tc 执行结果以 **信封** 形态返回，前端**只读 `rst_err` 判成功（`rst_err === ''` 即成功），绝不靠 HTTP 状态码**。错误码为 6 码闭集：

| 码 | 含义 | 你该查什么 |
|---|---|---|
| `ERR_NOT_FOUND` | 能力不存在 | 换有效指令域；可 `AI:text-cli;packages` 查看可用包 |
| `ERR_EXECUTION` | 执行失败，可重试 | 重试 1 次或检查指令参数 |
| `ERR_ROUTING` | 路由/网络失败 | 停 + 告警，查 `tc_endpoint` 可达性 |
| `INVALID_PARAMS` | 参数不合法 | 修正参数后重发 |
| `ACCESS_DENIED` | **Access Token 无效** / 端点安全层拒止 | 优先查 `access_token` 或端点 Token 鉴权/ST 前缀拦截 |
| `SERVICE_DENIED` | **Service Token 无效 / 提供方拒止** | 查 `service_token`；仅后端直连时出现 |

> 端口提示：本机桥用 `28050`（Service）；公网聚合端点用 `29050`。本机 `localhost` 双击场景如遇 CORS，前端会显式提示"请通过浏览器打开或配置同源/代理"，不会把网络层失败伪装成上述业务码。

## 6. 已知限制（诚实清单）

- **仅 OpenAI 风格下游**：不支持 Anthropic 等其它协议。
- **无系统提示预注入**：对话历史从空开始，但启用 tc 后会注入两条轻量 `SYSTEM_PROMPTS`（工具说明 + 语言指令），不膨胀上下文。
- **`max_tokens` / `temperature` 为内置固定值**：当前不在配置界面暴露。
- **白名单默认关闭**：任意 `http/https` 资源会被渲染（见 `privacy-checklist_zh.md` 安全模型）。
- **tc 为可选**：`tc_enabled=false`（默认）时行为与纯聊天版完全一致。
- **单文件 HTML 不执行 LLM 生成的 JS**：指令以 `AI:域;动作,参数` 文本原语消费，不 eval。

## 7. 安全收尾：责任在配置者一侧

tc-web-chat 把「掌控感」交还给你，但也意味着**数据流向由你填的后端决定**。它自身不收集数据、不内置模型，但请对你接入的服务保持基本警惕：

- API Key 写在聊天 Headers 里；
- `access_token` / `service_token` 决定 tc 运行时能否放行；
- 文件传给哪个 CDN 由你配置；
- 模型回复会渲染什么网页由你的后端输出决定。

前端已对资源 URL 做 `http/https` 校验、对 iframe 加 `sandbox`；人闸下拉把安全决策点暴露为可见控件（绝不替你做越权决策）。但 sandbox 不是银弹——请在你自建后端的输出层多做一层把关。
